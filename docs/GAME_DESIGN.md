# 『最後のコンビニ』ゲーム設計書

> ステータス: MVP設計案
>
> 更新日: 2026-08-24
>
> 本書の役割: 企画と実装判断の基準となる一次資料

## 1. ハイコンセプト

終末世界の深夜コンビニで、アルバイトの主人公としてレジに立つ。客が持ってきた商品を「売る」「販売を断る」「別の商品をおすすめする」という日常的な接客が、町の未来だけでなく過去や常識まで書き換えていく。

最初はおにぎり、飲料、日用品など普通の商品ばかりだが、やがて見覚えのない商品が混ざり始める。バーコードはなぜか通り、店長も平然と仕入れてくる。ゾンビ、ロボット、宇宙人、幽霊などの客も来店するが、主人公は勤務中には異常をうまく認識できない。

勤務後、主人公がスマホでニュースを見ると、接客結果に応じて世界線が変化している。プレイヤーはニュースや再来店した客から因果関係を推測し、次の勤務で何を売るかを決める。

## 2. プレイヤーに届けたい体験

1. **日常と異常の落差** — いつものコンビニ接客を淡々と続けるほど、異常さと笑い、不安が際立つ。

2. **遅れて理解する因果関係** — 選択直後に正解表示は出さず、勤務後のニュースと翌日の変化から結果を読み解く。

3. **善悪では割り切れない選択** — 奇妙な商品を売ること自体を悪にはしない。客、商品、おすすめの組み合わせによって、救済にも破滅にもなる。

4. **小さな接客が大きな結末になる感覚** — 一個の商品、一言のおすすめ、販売拒否が積み重なり、最後の世界を決定する。

5. **繰り返して因果を発見する楽しさ** — 一周では全容が分からず、別の販売パターンを試すことで客や世界の裏側が見える。

## 3. トーンと演出方針

- 基調は「淡々とした接客コメディ」から「静かな終末」への移行。
- 驚かせるホラーより、昨日までの常識が自然に書き換わっている不気味さを重視する。
- 主人公の独白は大げさにせず、「こんなのあったっけ……季節限定かな」のように合理化する。
- 店長は最後までコンビニ業務の言葉で異常を語る。
- 客は種族を笑いの対象にするだけでなく、それぞれ生活、目的、困りごとを持つ人物として描く。
- 世界が崩壊しても、レジ音、入店音、販促トークなどコンビニの日常音は変わらず残す。

店長の会話例:

> 「ゾンビ用弁当、最近よく出るんだよ」
>
> 「月曜日までに売り切ってくれ。月曜日が来ればだけど」

## 4. 基本ゲームループ

```text
店長から申し送り・新商品の紹介
        ↓
客が来店して商品をレジへ出す
        ↓
商品を確認・スキャンする
        ↓
売る / 断る / 一つおすすめする
        ↓
客の状態・世界線・店の評価が変化
        ↓
数組の接客を終えて勤務終了
        ↓
スマホでニュースと通知履歴を確認
        ↓
翌日の品ぞろえ・客・景色・会話が変化
```

勤務パートとニュースパートを一日一セットとする。

## 5. レジ接客

### 5.1 一回の接客

1. 客が短い会話とともに商品をカウンターへ出す。
2. プレイヤーが商品名、見た目、説明、価格を確認する。
3. 商品をスキャンする。異常商品も原則としてPOSを通過する。
4. 次のいずれかを選ぶ。
   - **売る**: 客に商品を渡し、基本効果を発生させる。
   - **断る**: 世界への効果を防げる場合があるが、客や店長との関係、売上に影響する。
   - **おすすめする**: レジ周辺の商品を一つ追加提案する。組み合わせによって基本効果が変化する。
5. レシート、客の一言、退店時の小さな演出で手触りを返す。ただし世界規模の結果はまだ見せない。

### 5.2 選択にコストを持たせる

販売拒否が常に安全策にならないよう、次を設ける。

- 店には一日の売上目標がある。
- 理由なく販売を断ると店長からの信用が下がる。
- 必要な商品を拒否された客が、別の危険な手段を取る場合がある。
- 異常商品にも、客や町を救う用途がある。
- おすすめは一接客につき一回とし、何を足すかに意味を持たせる。

数値は必要以上に画面へ表示しない。売上など主人公が知り得る情報は表示し、世界線スコアなどはニュースや背景から推測させる。

## 6. 世界線とスマホニュース

### 6.1 世界線が変わるタイミング

接客中は選択の効果を内部状態へ蓄積する。勤務終了後、主人公が店を出た時点でその日の結果が世界へ反映され、歴史・社会・町の状況が新しい世界線へ収束する。

### 6.2 主人公が改変を知れる理由

ライブ配信されるニュース本文や検索結果は新しい世界線へ書き換わる。一方、次の情報は改変前の断片を保持する。

- 勤務中に受信済みだったプッシュ通知
- スマホへ保存済みの画像やスクリーンショット
- コンビニのレシートとPOS履歴
- 主人公の曖昧な記憶

通知の見出しと、開いた記事本文が食い違うことで最初の違和感を作る。店内と、店内にあった物の一部が世界線改変の影響を受けにくい理由は、完全版で店長と店舗の秘密へつなげる。

### 6.3 一日のニュース構成

勤務後には原則3件のニュースを提示する。

1. **直接結果**: その日に扱った重要商品や客の結果。
2. **世界傾向**: 最も強くなった世界線を示す社会規模の記事。
3. **矛盾または生活記事**: 改変前との食い違い、普通の常連の変化、翌日への予告。

候補記事には表示条件と優先度を持たせ、条件を満たした中から重複しない役割の記事を選ぶ。結果をすべて説明せず、「あの商品が原因ではないか」と推測できる程度に留める。

### 6.4 MVPにおける三日間の認識変化

- **1日目**: 小さな食い違い。誤報や見間違いとして合理化できる。
- **2日目**: 「昔からそうだった」と報じられる歴史改変。通知と本文が明確に矛盾する。
- **3日目**: 主人公が、自分の接客と世界線変化の関係を理解する。最後の客への対応が結末を決める。

完全版ではこの流れを七日間へ広げ、気づき、検証、介入、最終選択の段階を細かく描く。

## 7. 内部状態

### 7.1 四つの世界線

| ID | 世界線 | 主な要素 | 平和的な可能性 | 破滅的な可能性 |
|---|---|---|---|---|
| `undead` | 不死者 | ゾンビ、感染、蘇生 | 人間と不死者の共生 | 感染拡大、飢餓 |
| `machine` | 機械 | ロボット、自動化、自我 | 労働解放、感情の獲得 | 管理社会、機械反乱 |
| `cosmic` | 宇宙 | 宇宙人、異星技術、移住 | 交流、避難、技術提供 | 侵略、地球の接収 |
| `spirit` | 霊界 | 幽霊、未練、彼岸 | 和解、供養、再会 | 生死の境界崩壊 |

世界線は善悪の値ではない。同じ軸が強くても、`stability`や客の個別状態により平和的・破滅的な結果が変わる。

### 7.2 補助状態

- `stability`: 異なる存在が共存できる安定度。低いほど世界線同士が衝突する。
- `awareness`: 主人公が改変を認識し、意図的に介入できる度合い。
- `manager_trust`: 店長からの信用。販売拒否、売上、特定の接客で変化する。
- `flags`: 一度きりの重要事実。商品販売、記事閲覧、秘密の発見など。
- `customer_states`: 各客の生存、関係、目的、変化段階。
- `seen_news`: 表示済みニュース。周回中の重複を防ぐ。

概念上の状態例:

```yaml
day: 1
world:
  undead: 0
  machine: 0
  cosmic: 0
  spirit: 0
stability: 0
awareness: 0
manager_trust: 0
flags: []
customer_states: {}
seen_news: []
```

## 8. 分岐設計の原則

### 8.1 シーンを巨大な分岐ツリーにしない

選択肢から次のシーンへ直接枝を伸ばし続けるのではなく、すべての選択を共通状態へ反映する。客、ニュース、翌日の品ぞろえ、エンディングはその状態を条件として参照する。

### 8.2 結果は最低二回返す

重要な選択は、可能な限り次の二つでフィードバックする。

- 直後または勤務後のニュース
- 翌日以降の客、商品、背景、会話

これにより、記事だけを読む結果画面にはせず、世界の変化として実感させる。

### 8.3 正解を商品名だけで明示しない

「危険」「善良」と書かれた分かりやすい選択ではなく、客の会話、商品の用途、過去のニュースを組み合わせて判断させる。

### 8.4 重要な組み合わせだけを特別扱いする

すべての商品同士に固有反応を作る必要はない。物語上重要な`customer × requested_item × recommended_item`だけ特殊結果を定義し、それ以外には共通反応を返す。

## 9. MVPの制作範囲

まず、完全版の構造を検証できる縦切りの完成品を作る。

| 項目 | MVP |
|---|---|
| 日数 | 3日間 |
| 一日の接客数 | 5〜6組 |
| 想定プレイ時間 | 30〜45分 |
| 主要な再登場客 | 6人 |
| 重要な異常商品 | 12個 |
| 通常商品 | 演出用の少数セット |
| ニュース | 15〜20本 |
| 世界線 | 4軸 |
| エンディング | 5種類 |
| 主なロケーション | 店内、勤務後のスマホ画面 |
| 音声 | ボイスなし |

主要客6人の内訳:

- 不死者世界線に関わる客
- 機械世界線に関わる客
- 宇宙世界線に関わる客
- 霊界世界線に関わる客
- 変化の基準となる普通の常連2人

店長は主要客とは別枠とし、毎日の仕入れ、申し送り、主人公の評価、店舗の秘密を担当する。

## 10. MVPの三日構成

### 1日目: 違和感

- 接客の大半は普通。
- 異常商品は、限定商品やパッケージの冗談にも見える程度から始める。
- 最後に一人だけ説明のつかない客を出す。
- ニュースでは小さな改変を一つ確認できる。

### 2日目: 検証

- 店長の仕入れに明らかな異常商品が増える。
- 1日目の客が変化して再来店する。
- 複数の世界線に関わる選択肢を提示する。
- 通知履歴とニュース本文が矛盾し、主人公が改変を疑い始める。

### 3日目: 介入

- 普通の客と異常な客の立場が逆転し始める。
- 過去二日の結果に応じて客の目的と品ぞろえが変わる。
- 主人公が接客の影響を理解した状態で最後の判断を行う。
- 四つの単独世界線、または全面崩壊のいずれかへ到達する。

## 11. 客・商品・おすすめの例

以下はMVP用のたたき台であり、名称と人物設定は実制作時に調整する。

| 客 | レジへ出す商品 | おすすめAと結果 | おすすめBと結果 |
|---|---|---|---|
| ゾンビの会社員 | 生肉おにぎり | マスク → 人間社会へ溶け込む | レジ横チキン → 食欲が暴走する |
| 配送ロボット | 自我対応乾電池 | 少女漫画 → 感情を学ぶ | 精密ドライバー → 自己改造する |
| 幽霊の少女 | 帰魂線香 | 写真プリント券 → 家族と再会する | 盛り塩 → 消滅または封印される |
| 宇宙人旅行者 | 無重力カップ麺 | 観光ガイド → 地球へ残る | モバイル電源 → 宇宙船を修理する |

この4組に各3商品を関連づけることで、MVPの重要商品12個を構成できる。通常商品も組み合わせに利用し、「普通の商品が異常な未来を変える」展開を入れる。

普通の常連は世界線の温度計として使う。例として、昨日は会社員だった人物が「人間専用レジ」に並ぶ、学校のニュースが「生徒の充電時間」に変わるなど、生活の細部で改変を示す。

## 12. エンディング設計

### 12.1 MVPで実装する5種類

| # | 仮題 | 条件の中心 |
|---|---|---|
| 1 | 夜明けのない街 | `undead`が単独で優勢 |
| 2 | 完全自動営業 | `machine`が単独で優勢 |
| 3 | 最終便 | `cosmic`が単独で優勢 |
| 4 | 街全体が彼岸 | `spirit`が単独で優勢 |
| 5 | 在庫混線 | 複数軸が衝突し、`stability`が低い |

### 12.2 完全版の15種類

MVPの状態構造を変えず、七日間のコンテンツと次の結末を追加する。

#### 単独世界線: 4種類

1. 夜明けのない街（不死者）
2. 完全自動営業（機械）
3. 最終便（宇宙）
4. 街全体が彼岸（霊界）

#### 二世界線の混合: 6種類

5. 永遠の夜勤（不死者＋機械）
6. 星間感染（不死者＋宇宙）
7. 死者の渋滞（不死者＋霊界）
8. 地球支店（機械＋宇宙）
9. 幽霊OS（機械＋霊界）
10. 彼岸航路（宇宙＋霊界）

#### 全体状態: 3種類

11. いつもの朝（すべての世界線が低い）
12. 24時間営業（複数世界線が共存し、`stability`が高い）
13. 在庫混線（複数世界線が衝突し、`stability`が低い）

#### 秘密: 2種類

14. 来週のシフト（店長と店舗の秘密に関する条件）
15. 最後の返品（主人公が世界線改変の仕組みを理解した真相系条件）

名称と内容は仮案。15種類という構造と判定方式を先に固定し、シナリオ制作で磨く。

### 12.3 判定方針

- 秘密エンドは専用フラグと`awareness`を要求する。
- 全体状態エンドは四軸の合計、差、`stability`で判定する。
- 混合エンドは上位二軸が閾値以上かつ差が小さい場合に判定する。
- 単独エンドは一位の軸が閾値以上で、二位との差が十分ある場合に判定する。
- すべての状態にフォールバックを用意し、エンディング未決定を発生させない。
- 判定は優先度をデータとして持ち、コードへ個別の`if`を増殖させない。

## 13. データ駆動のコンテンツ構成

ゲームエンジンにかかわらず、次の単位をコードから分離する。

- `items`: 商品名、説明、価格、見た目、基本効果
- `customers`: 名前、立ち絵、通常会話、状態、再登場条件
- `encounters`: 日、客、提示商品、会話、選択結果
- `recommendation_pairs`: 特別な商品組み合わせと効果
- `news`: 見出し、本文、表示条件、役割、優先度
- `endings`: 条件、優先度、演出、最後の会話

概念例:

```yaml
id: encounter_robot_battery_day2
day: 2
customer: delivery_robot
requested_item: self_aware_battery
choices:
  sell:
    effects:
      world.machine: 2
  refuse:
    effects:
      manager_trust: -1
      flags: [robot_refused]
  recommend:
    comic:
      effects:
        world.machine: 1
        stability: 2
        customer_states.delivery_robot: empathetic
    screwdriver:
      effects:
        world.machine: 3
        stability: -1
        customer_states.delivery_robot: self_modified
```

条件表現は、次の組み合わせを扱えるようにする。

- `all` / `any` / `not`
- 世界線や補助状態の閾値
- フラグの有無
- 客の状態
- 日数
- 閲覧済みニュース

## 14. ニュースデータの要件

各ニュースには最低限、次を持たせる。

| 項目 | 用途 |
|---|---|
| `id` | 一意な識別子 |
| `headline` | 一覧に出る見出し |
| `body` | 開いた記事本文 |
| `role` | direct / trend / discrepancy / local |
| `conditions` | 表示条件 |
| `priority` | 同時成立時の優先度 |
| `effects_on_read` | 認識度やフラグへの効果 |
| `exclusive_group` | 内容が矛盾する記事の同時表示防止 |

通知と記事本文を別フィールドにできる設計にする。これにより、改変前の通知見出しと改変後の記事本文を意図的に食い違わせられる。

## 15. 実装時に守ること

- シナリオ本文や分岐条件を画面コードへ直書きしない。
- コンテンツIDは一度公開したら安易に変更しない。セーブデータとの互換性に使う。
- 乱数がある場合も、デバッグ用にシードを固定できるようにする。
- 任意の世界状態からニュースとエンディングを確認できるデバッグ画面を用意する。
- 全エンディングに到達可能かを自動テストできる形にする。
- 選択結果をログへ残し、不具合時に「何を売ったか」を再現できるようにする。
- MVPでは機能追加より、一周を最後まで遊べることを優先する。

## 16. MVP完成条件

次をすべて満たした時点をMVP完成とする。

- タイトルから3日目終了まで中断せずプレイできる。
- 売る、断る、おすすめするの三操作が結果へ反映される。
- 同じ日の異なる選択によって、翌日の客または会話が変わる。
- 勤務後に3件のニュースが条件に応じて表示される。
- 通知と本文の食い違いから、主人公が世界線改変へ気づく流れが成立する。
- 5種類すべてのエンディングへ到達できる。
- セーブ、ロード、最初からやり直す操作ができる。
- 一周後、別の選択を試したくなる未回収の手掛かりが残る。

## 17. 完全版への拡張

MVP完成後、コードの主要構造を変更せず次を追加する。

- 3日間から7日間へ延長
- 主要客と商品、ニュースの追加
- 二世界線混合エンド6種類の追加
- 通常、共存、秘密エンドの追加
- 店外の景色と店内商品の段階的変化
- 周回で解放されるニュースアーカイブ、商品図鑑、エンディング一覧
- 主人公、店長、コンビニそのものの真相

## 18. 実装開始前に決める事項

以下は現時点では固定せず、最初のCodexプロジェクトで決定する。

- 使用するゲームエンジンとプログラミング言語
- PC、Web、モバイルなど対象プラットフォーム
- 2D立ち絵、ピクセルアート、3Dなどのビジュアル形式
