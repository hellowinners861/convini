# 『最後のコンビニ』実装設計書

> ステータス: 5日間MVPの実装基準
> 設計担当: GPT-5.6 Sol Ultra
> 更新日: 2026-08-24
> 実装担当: GPT-5.6 Luna Max

この文書は、[ゲーム設計書](GAME_DESIGN.md)の未決定事項を固定し、実装中の判断基準を与える。矛盾がある場合は、ユーザーの指示、ゲーム設計書、この文書の順に優先する。

## 1. 固定する製品判断

| 項目 | MVPの決定 |
|---|---|
| 仮タイトル | 最後のコンビニ |
| 対象 | PCブラウザ。1280×720以上を主対象とし、800×600と200%ズームでも操作可能 |
| 形式 | 日本語、2D、横画面、マウス中心。キーボードでも全操作可能 |
| 技術 | Vite + React + TypeScript |
| 描画 | DOM + CSS Modules。Canvas、3D、ゲームエンジンは使わない |
| 状態管理 | 純粋関数のゲームエンジン + React `useReducer` + Context |
| コンテンツ | `src/content`のTypeScriptデータ。画面へ本文や分岐を直書きしない |
| 検証 | Zod、Vitest、Playwright、axe |
| 保存 | `localStorage`のオートセーブ1枠 + 周回メタ |
| 乱数 | MVPでは使わない。同条件は優先度降順、ID昇順で決定 |
| プレイ時間 | 初見60〜90分 |
| MVP範囲 | 5日、29接客、主要客6人、重要商品12個、候補ニュース24〜30本、5エンド |

バックエンド、ログイン、クラウドセーブ、PWA、ボイス、3D、多言語化、シナリオ管理画面はMVP外とする。

## 2. 体験の柱

1. 異常を警告色で説明せず、普通のレジ業務として扱う。
2. 選択直後には客の一言とレシートだけを返し、世界規模の結果は勤務後に返す。
3. 通知、記事本文、レシート、翌日の客という複数の証拠で因果を推測させる。
4. 売る、断る、おすすめのどれも常に正解にはしない。
5. 世界線の内部数値は通常UIに表示しない。
6. 重要な選択はニュースと再来店の最低二回で返す。

## 4. 重要商品12個

| 軸 | 基本商品 | 共存側のおすすめ | 暴走側のおすすめ |
|---|---|---|---|
| 不死者 | 生肉おにぎり | マスク | レジ横チキン |
| 機械 | 自我対応乾電池 | 少女漫画 | 精密ドライバー |
| 宇宙 | 無重力カップ麺 | 観光ガイド | モバイル電源 |
| 霊界 | 帰魂線香 | 写真プリント券 | 盛り塩 |

基準効果:

- 基本商品を売る: 対応軸 `+2`
- 共存側をおすすめ: 対応軸 `+1`、`stability +2`
- 暴走側をおすすめ: 対応軸 `+3`、`stability -2`
- 断る: 客固有の危険な代替行動により対応軸 `+1`、`stability -1`、`managerTrust -1`
- 5日目の最終客へ販売成立: 対応軸へ追加の収束補正 `+2`
- 最終拒否: `convergence_refused`、`stability -2`

数値は調整可能だが、5エンドのゴールデンルートを壊す変更は禁止する。盛り塩は一人を封じても未練を町へ押し出すため、霊界軸上昇と安定度低下を伴う。

## 5. 五日構成と全29接客

### 1日目「違和感」— 5接客

日常の基準を覚えさせ、最後だけ合理化不能にする。

1. 夜勤タクシー運転手: コーヒーとガム。スキャン、三操作、レシートのチュートリアル。
2. 宮下: 黒コーヒーとサンドイッチ。病院名、日付、夜勤体制を基準情報にする。
3. 蓮: 牛乳と鉛筆。「うちは一人っ子」と話し、家族写真を伏線化。
4. 早川: 生肉おにぎり。青白さを夜勤疲れ、商品を季節限定として合理化できる。
5. ほたる: 帰魂線香。入店音は鳴るがドアが動かず、POSだけは正常。

ニュースは小さな直接結果、誤報にも見える世界傾向、軽い時刻矛盾の3件。

### 2日目「反復」— 6接客

前日の結果を客本人と普通の常連から返し、機械・宇宙軸を導入する。

1. 宮下: 早川への対応に応じ、平穏な不死者患者、咬傷、行方不明のいずれかを語る。
2. HAKO-3: 自我対応乾電池。最初は高度な配送端末にも見える。
3. 工事作業員: 弁当と軍手。理由のない拒否が売上と店長信用へ影響することを再提示。
4. 蓮: ほたるへの対応を、姉の記憶、写真の影、理由のない喪失感として返す。
5. ミュー: 無重力カップ麺。コスプレ客にも見えるが翻訳表示が一瞬ずれる。
6. 早川再来: マスクなら社会適応、チキンなら暴走、拒否なら極端な空腹状態。

ニュースでは保存通知と現在の記事本文を明確に食い違わせる。

### 3日目「検証」— 6接客

四軸を再確認し、主人公がレシートへ印をつけて因果を試す。

1. 老人: 新聞。商品の日付と、本人が当然視する改変後の歴史を矛盾させる。
2. HAKO-3再来: 漫画なら共感、ドライバーなら自己改造、拒否なら配送停止。
3. ほたる再来: 写真なら蓮との関係、盛り塩なら反射越しの声として返す。
4. 宮下: 病院を、不死者病棟、全自動診療、異星検疫、霊安病棟の温度計にする。
5. ミュー再来: 観光ガイドかモバイル電源を意識的に提案させる。
6. 蓮: 保存写真、記事、レシートを並べ、主人公が因果仮説を言葉にする。

`awareness`条件で証拠比較画面を解放する。数値そのものは見せない。

### 4日目「介入」— 6接客

個人向けだった商品を町全体へ拡大し、共存か暴走かを意図的に選ばせる。

1. 宮下: 「誰を人として救急搬送するか」の変化から人間側のコストを語る。
2. 早川: 同僚全員分。マスクは社会適応、チキンは集団的食欲暴走。
3. HAKO-3: 配送網全体分。漫画は共感学習、ドライバーは一斉自己改造。
4. ミュー: 到着予定の仲間分。ガイドは交流、電源は母船への座標送信。
5. ほたる: 町の迷える死者分。写真は個別の和解、盛り塩は大規模封印と境界破損。
6. 蓮: 姉の写真と過去レシート。丁寧な接客で `human_anchor`、拒否で孤立。

ニュースは最大の直接結果、上位二軸の協調または衝突、5日目の収束予告。

### 5日目「収束」— 6接客

日開始時のスナップショットで四異常客を弱い軸から強い軸へ並べる。同点は未解決度、最後に作用した軸、固定ID順で決める。

1. 宮下: 現在の世界で救急対象となる存在を語る。
2. 開始時4位の軸の客: 短い最終接客。
3. 開始時3位の軸の客: 別軸へ追いつく最後の機会。
4. 開始時2位の軸の客: 首位との衝突可能性を提示。
5. 蓮: 「朝になったら、これは誰の写真になる？」と旧世界の写真を預ける。
6. 開始時首位の軸の客: 最後の一個を持参し、収束補正を伴う最終判断。

接客中に背景を即時改変しない。勤務終了後のニュース3件を読み終えた時点でエンディングへ進む。

  runNumber: number;

`GamePhase`は `briefing`、`encounter`、`shiftSummary`、`news`、`ending`、`runSummary` の判別共用体にする。接客には `intro`、`scan`、`decision`、`result` の段階を持たせる。

## 9. 日次スロット

条件一致した全接客を並べず、各日5〜6個の固定スロットを定義する。各スロットは条件付き候補と必須fallbackを一つ持つ。

```ts
interface EncounterSlot {
  id: string;
  candidates: Array<{
    encounterId: string;
    conditions: Condition;
    priority: number;
  }>;
  fallbackEncounterId: string;
}
```

選定は条件成立、優先度降順、ID昇順。日開始時に全スロットを解決し、その日の途中では変えない。

## 10. 条件と効果

任意パス、文字列式、`eval`は禁止する。

条件は `true`、`all`、`any`、`not`、数値比較、flag、客状態、既読ニュース、首位軸を扱う。数値参照は世界線、安定度、認識度、店長信用、売上、日数、首位値、二位値、差、強軸数に限定する。

効果は世界線加算、補助値加算、売上加算、flag設定、客状態設定に限定する。

- 評価と適用は純関数。
- 一つのOutcomeの効果は同じ開始スナップショットへ原子的に適用。
- 同じ数値対象は合算後に一度だけ反映。
- 同じOutcomeで一人の客へ複数状態を設定したら検証エラー。
- 履歴を条件にする場合はログを検索せず、明示的なflagを立てる。
- Reducer内で時刻、乱数、ストレージを参照しない。

## 11. おすすめ解決

特別反応は `customer × requestedItem × recommendedItem` で定義する。

1. 完全一致するpairを集める。
2. 条件成立だけを残す。
3. 優先度降順、ID昇順で一つを選ぶ。
4. `append-base-sale`は基本販売効果へ追加する。
5. `replace-base-sale`は基本販売効果を置き換える。
6. 一致なしは共通のおすすめ反応を使う。

同優先度で複数成立するデータは起動時検証を失敗させる。

## 12. ニュース選定

一日3枠を必ず `direct`、`trend`、`discrepancy` で埋める。1日目の3枠目だけ `local`を優先できる。

1. 日付一致、条件成立、今周回で未表示の候補を作る。
2. 各枠で優先度降順、ID昇順の一件を選ぶ。
3. 採用済み `exclusiveGroup` と衝突する候補を除く。
4. 各日、各枠に無条件の低優先度fallbackを持たせる。
5. 3件を一括保存し、リロードで再選定しない。
6. 記事初読時のみ `effectsOnRead` を適用する。
7. 3件すべてを一度開くまで次の日へ進めない。

`notificationHeadline`は勤務中の旧世界、`headline`と`body`は収束後の世界を表す。

## 13. エンディング

判定順:

1. 在庫混線: 上位二軸がともに7以上、差2以内、`stability <= -4`。または最終拒否かつ4以上の軸が3本以上。
2. 単独世界線: 最高軸を選ぶ。
3. 完全同点: 5日目の収束軸で決める。
4. それでも決まらない場合だけ在庫混線へfallback。

`stability`と客状態は単独エンド内の平和的、破滅的な演出差に使い、6個目のエンドにはしない。

ゴールデンルート:

- 早川だけ暴走側を重ねる → 夜明けのない街
- HAKO-3だけ暴走側を重ねる → 完全自動営業
- ミューだけ暴走側を重ねる → 最終便
- ほたるだけ暴走側を重ねる → 街全体が彼岸
- 四人すべて暴走側、または全拒否 → 在庫混線

`managerTrust`低下で勤務を打ち切ったり重要選択をロックしたりしない。会話、売上評価、ヒント量だけを変える。

## 14. セーブと周回

```text
last-convenience:run:v1
last-convenience:meta:v1
last-convenience:settings:v1
```

- 選択確定後、ニュース選定後、記事初読後、翌日開始時、エンド確定時に保存。
- Zodでロードを検証し、壊れたセーブは部分復元せずリセット案内を出す。
- 非互換contentVersionではランだけをやり直し、周回メタと設定は残す。
- 「はじめから」はランだけを確認付きで消す。
- 周回で解放エンドとニュースアーカイブを保持する。
- エンド確定とメタ更新は同じIDで二重加算しない。

## 15. UIデザインシステム

方向は「深夜の蛍光灯」「使い込まれたPOS」「新聞の紙面」「静かなスマホ画面」。ホラーゲームの赤黒や、派手なサイバーパンクにはしない。

色:

- `--ink: #171b24` 深い青墨
- `--night: #0d1520` 店外
- `--paper: #f3eedf` レシートと記事
- `--fluorescent: #c8e7d4` 蛍光灯の青緑
- `--amber: #e7b66a` 深夜の温かい誘導色
- `--vermilion: #c95745` 拒否、警告の限定色
- 世界線色は背景の小物にだけ薄く使い、数値メーターにはしない。

タイポグラフィ:

- 日本語は `system-ui, "Yu Gothic UI", "Hiragino Sans", sans-serif`。
- 見出しは中太、本文は400、レシートは等幅。
- 装飾的な疑似手書きフォントを本文へ使わない。

レイアウト:

- 1100px以上: 左55%に店内と客、右45%に会話、商品、操作。
- 720〜1099px: 上に客、下に会話と操作。
- 719px以下: 一列。操作部を下部stickyにする。
- 画面全体をスクロールし、狭い内部スクロール領域を作らない。

操作:

- スキャン前は三操作を無効化。
- 三操作は常に画面へ表示し、1/2/3キーは補助にする。
- おすすめはモーダルで商品絵、名前、価格、短い説明を比較する。
- 選択確定前に一度だけ確認し、確定後はレシートをアニメーション表示する。
- 日付、売上、客数、セーブ状態など主人公が知り得る情報だけを表示する。

## 16. 日ごとの背景変化

| 日 | 店内 | UI |
|---|---|---|
| 1 | 通常棚、蛍光灯、普通の夜景 | 商品名、価格、三操作だけ |
| 2 | 首位軸を示す小物を一つ追加 | 保存通知と記事見出しを並べ、レシート履歴を解放 |
| 3 | 首位軸を屋外、二位軸を棚札へ反映 | 通知、記事、POS履歴の比較を解放 |
| 4 | 上位二軸を同時表示。高安定は共存、低安定は矛盾 | レシートへ主人公の手書き印 |
| 5 | 4日目終了時の世界を勤務中は固定 | 旧レシートと新POS表記を食い違わせる |

世界線の視覚語彙:

- 不死者: 夜の長さ、青白い肌、マスク、閉店しない病院
- 機械: 無人棚、整いすぎた陳列、配送箱、反復する表示
- 宇宙: 空の光、観光案内、丸い記号、わずかな無重力
- 霊界: ガラス反射と実人数の不一致、濡れた足跡、写真の欠落

## 17. アートディレクション

客と商品は、編集イラストのようなガッシュ、水彩、色鉛筆、かすれたインクの混合。紙へ描いてスキャンしたような粒子と、線幅の揺れを残す。

客:

- 腰上または膝上、レジ越しの3/4向き。
- カメラ位置、光源、輪郭の太さを全員で統一。
- 表情は抑えめ。異常種族も生活者として描く。
- 左右対称を崩し、服の皺、髪、筆跡に小さな不均一を残す。
- 一人物につき通常、共存、暴走の差分を同じ原画から作る。

商品:

- 斜め上から見た小さな静物画。
- 形と色だけで区別できる明快なシルエット。
- 実在ブランドは使わない。
- 商品名や価格は画像へ焼き込まずHTMLで重ね、意味不明なAI文字を防ぐ。

画像生成を使う場合:

1. まず一人と三商品だけを生成し、線、紙目、色、光源の基準画にする。
2. 基準画を参照して残りを同じ作者の連作として生成する。
3. 手、指、瞳、パッケージ文字、左右の小物、切り抜き境界を人の目で確認する。
4. 違和感がある箇所は局所修正し、アップスケールだけで済ませない。
5. 生成物をそのまま全面へ敷かず、UIの余白とトリミングで編集する。

避けるもの:

- 光沢の強い3D、過度なアニメ塗り、均一すぎる線
- ネオンだらけのサイバーパンク、過剰な被写界深度
- 皮膚や包装の不自然な高精細、左右対称の顔
- 六本指、溶けた小物、意味不明な日本語、実在ロゴ
- 全人物が同じ顔、同じポーズ、同じ感情

画像が揃う前も完成して見えるよう、CSSの紙テクスチャ、色面、人物名入りの手描き風シルエット、商品パッケージの単純図形をfallbackとして実装する。外部画像取得を必須にしない。

## 18. モーションと音

- 入店ベル、スキャン音、レシート、スマホ通知を短い音で区別する。
- 音はユーザー操作後に開始し、常設ミュートを置く。
- レジ音と入店音は世界が崩れても変えない。
- モーションは150〜350ms。紙の滑り、蛍光灯の一度だけの明滅、スマホの小さな振動に限定。
- `prefers-reduced-motion`では揺れ、点滅、長い遷移を停止する。
- 音や色だけで結果を伝えず、必ずテキストを併記する。

## 19. アクセシビリティ

- クリック対象はbutton、ニュースは見出し、list、articleを正しく使う。
- モーダルはfocus trap、Esc、閉じるボタンを持つ。
- 画面遷移後は主見出しへfocusする。
- スキャン、売上、レシートは `aria-live="polite"`。
- visible focus、本文4.5:1以上、色以外の状態表現。
- 200%ズームで本文と操作を隠さない。
- キーボードだけでタイトルからエンディングまで進める。

## 20. デバッグ

- 四世界線、安定度、認識度、信用、売上の編集
- flagと客状態の編集
- 条件trace
- ニュース候補と除外理由
- エンド候補と失敗条件
- セーブJSONのexport/import
- ランのみ、またはメタ込みの消去
- 5本のゴールデンルート自動再生
- eventLogと効果差分

## 21. テスト

Unit:

- `all/any/not`と比較演算子、境界値
- 効果の原子的合算
- おすすめpairのappend/replace
- 同条件の決定性
- 各日5〜6接客と必須fallback
- 各日ニュース3件、重複なし、排他
- 記事効果が一度だけ適用
- 5エンドの閾値、fallback、ゴールデンルート
- セーブスキーマと非互換処理

Content validation:

- 全ID一意、全参照先が存在
- 各日5〜6slot、各slotにfallback
- 全接客にsell、refuse、default recommend outcome
- pairの曖昧な同順位成立なし
- 各日3ニュース枠にfallback
- エンディングの全状態fallbackが一つ

E2E:

- 新規開始から一接客完了
- スキャン前は決定不可
- おすすめは一接客一回
- 選択後リロードで同じ結果へ復帰
- 通知と本文の食い違い
- 5日を完走し各エンドへ到達
- 周回後も解放情報が残る
- キーボードだけで一周
- axeの重大違反なし

## 22. 実装順

1. Vite/React/TypeScript、lint、test、buildの足場。
2. domain型、条件、効果、日次スロット、ニュース、エンドの純関数とUnit test。
3. 仮データで「申し送り→スキャン→選択→レシート→ニュース→翌日」の一日縦切り。
4. 5日29接客、主要客6人、重要商品12個を投入。
5. 候補ニュース24〜30本、通知差分、5エンド、ゴールデンルート。
6. セーブ、ロード、最初から、周回メタ。
