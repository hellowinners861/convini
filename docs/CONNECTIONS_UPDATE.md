# 接客とつながりのアップデート

2026-09-07。既存の5日間・29接客・5エンドを土台に、用途を確かめる会話、紙の記録を共有する相手、常連同士の因果を追加した。

## 遊び方

接客の会計前に、一組につき一つだけ質問できる。常連との販売成立後にはレシートを渡せる。いずれも任意で、元の売る・断る・おすすめする経路は引き続き遊べる。

レシートを渡した相手は、再来店時に改変前の記録を持参する。接客ノートには実際に聞いた言葉、会計の控え、読んだ記事と元の通知だけを表示する。物語のつながりは、該当する常連の会話を経てからノートへ収録し、先の展開を明かさない。

## 新しい用途（分岐のネタバレ）

| 日・客 | 会話が出る条件 | 会話と販売 | 返ってくる結果 |
|---|---|---|---|
| 3日目・HAKO-3 | 以前にレシートを渡した、または共感を学んでいる | 車輪だけを直す約束をして精密ドライバーをすすめる | 病院への配送。宮下の連絡と4日目の早川の父の話 |
| 4日目・ミュー | ミューと宮下の両方にレシートを渡している | 病院へ救助艇だけを呼ぶ相談をしてモバイル電源をすすめる | 母船への座標送信を避けた病院の避難経路 |
| 4日目・ほたる | 蓮にレシートを渡し、ほたるが家族に思い出されている | 家の外へ境界を引く相談をして盛り塩をすすめる | ほたるを封じず家族を守る境界 |

質問だけでは販売や世界への影響は発生しない。用途を約束した日の当該商品の販売時だけ、元の暴走側の効果を共存側へ置き換える。同じ約束を翌日以降へ流用しない。会話をしなかった場合は従来の効果を使う。

## 実装と保存

- 会話と受け渡しの文面は `src/content/connections.ts` に集約。接客データの任意フィールドとして検証する。
- 条件付きの組み合わせは `src/content/pairs/contextPairs.ts`。従来の8組と追加3組の計11組。各商品組には無条件の基本ルールを一つ維持する。
- 質問は、その接客に属すること、会話条件を満たすこと、まだ別の質問をしていないことをコントローラーで検証する。
- レシートは販売成立後のみ、一接客一回。販売拒否では渡せない。渡しても売上や接客イベントを重ねて加算しない。
- 既存の `flags` を使用し、セーブ形式とコンテンツIDを維持。質問と受け渡しを即時保存の対象に追加した。
- 古い保存データに追加フラグがなくても復元できる。元の5つのゴールデンルートは維持する。

## 検証

`npm run check` で型、コンテンツ参照、元のルート、UI、保存互換性を検証する。追加の接客テストは、3つの協力を成立させて5日間を完走し、各会計後の保存・復元を検証する。UIテストでは、質問と受け渡しが操作直後に保存され、再起動後も同じ会話・結果に戻ることを確認する。

`npm run test:e2e` は実ブラウザーで起動、接客、キーボード操作、保存、ニュース、エンディングを確認する。
