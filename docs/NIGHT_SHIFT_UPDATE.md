# 深夜の接客・観察・証拠照合

既存の5夜・29接客・15記事、会話、レシートの受け渡し、接客ノートを維持し、次の体験を追加した。

## 遊び方

「ひと声の接客」は商品スキャン後に選べる。1場面に一度だけ返答を決める。会計せずに伝えられる約束や用途確認はその場で記録し、袋・温め方・電源の受け渡しは販売成立時に反映する。販売を断れば商品は渡らず、追加料金も発生しない。

| 夜 | 新しい場面 | 結果の返し方 |
| --- | --- | --- |
| 1 | ほたるに店の袋を渡す | 3夜目の会話、観察、個別の後日談。盛り塩による封印は袋では解除できない |
| 2 | 早川のおにぎりを温めるか、常温で渡すか | 同僚への香りの影響、4夜目の会話 |
| 2→3 | 蓮の名前を覚えると約束し、別の名札を付けた翌夜に呼びかける | 4・5夜目の会話、名前に関する後日談 |
| 3 | HAKO-3の修理伝票を確かめる | 精密ドライバーが薬品冷蔵庫を直す道具になる。既存の車輪修理の約束も同時に成立できる |
| 3→4 | ミューと病院、最後の電源の行き先を選ぶ | 取り置き中はミューへ販売できない。宮下へ渡す場合は1,980円を追加会計。ミューへ販売済みなら二重に渡せない |

電源の再入荷は4夜目の二便目、宮下の出発後。4夜目のミューへの接客では、新しい入荷分を販売できる。この時刻は3夜目に提示する。

## 観察と証拠

- 勤務前か客の退店後に、窓・防犯カメラ・レジ横の棚から1夜に一か所を選べる。未選択の場所は次の周回で調べられる。
- 観察した内容と追加接客の返答は、全画面から開ける接客ノートにも残る。
- ニュースを開いた後も元の通知を残す。ニュース画面の手帳で記事と実際の取引記録を組み合わせ、仮説を保存する。
- 保存できるのは既読の記事と、その記事の日までに発生した取引だけ。販売拒否の記録も比較できる。
- 翌夜以降、該当する客（または記録を調べている蓮）に1接客につき一つ提示できる。
- 記憶の裏付けが取れる組み合わせと、未確定の仮説を区別する。未提示の仮説は組み替え可能。提示後の記録は会話の履歴として固定する。

## 実装と保存

- 追加シナリオ：`src/content/nightShift.ts`
- 任意操作・在庫・文脈付き効果：`src/engine/nightShift.ts`
- 画面部品：`src/components/NightShift.tsx`
- 状態は既存の`flags`と取引ログを使い、V1保存構造を拡張しない。新しい操作も自動保存の対象。
- 古いV1セーブの電源販売は取引ログから読み取るため、在庫フラグがなくても二重販売を防ぐ。
- 従来の会話、レシート受け渡し、病院への配送・救助・家族の境界の分岐を維持する。
- 従来の5種類の世界線エンディングに、選択に応じた6種類の個別エピローグを添える。
